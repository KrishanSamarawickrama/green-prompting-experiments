# Green Capacity Experiment with Ollama

This repository contains a ready-to-run experiment harness to evaluate whether prompt engineering can improve the energy efficiency of code generated by Large Language Models (LLMs). It was created for a dissertation project and all materials are provided to support replication and extension.

The core research question is: **Can prompt design increase the "green capacity" of LLMs to produce energy-efficient code?**

This is tested via a controlled, fully reproducible study using:
- **LLM Inference**: Two open models (DeepSeek-Coder-6.7B, Qwen-2.5-Coder-7B) served locally via **Ollama**.
- **Tasks**: Six representative software engineering tasks.
- **Prompts**: Four distinct prompt styles (baseline, chain-of-thought, efficiency-focused, and tagged-explained).
- **Execution Measurement**:
    - Runtime & FLOPs: **`perf`**
    - Peak Memory: **`tracemalloc`**
    - Generation Energy: **CodeCarbon**
    - Execution Energy: **`perf`** (RAPL `power/energy-pkg/`)

The study finds that prompt structure is a primary driver of code efficiency, with a tagged-explained format showing the most consistent gains.

## Quick Start

### 1) Prerequisites
- Linux (tested on Xubuntu 22.04)
- Python 3.10+
- `perf` (from `linux-tools`): `sudo apt install linux-tools-common linux-tools-$(uname -r)`
- **Ollama**: Follow installation instructions at [ollama.com/download](https://ollama.com/download).

### 2) Pull Models
The experiment uses two models. Pull them via the Makefile target:
```bash
make ollama-pull
```

### 3) Install Dependencies
Set up the Python virtual environment and install requirements:
```bash
make init
```

### 4) Run All Experiments
The `run_all.sh` script executes the full experimental plan: generating code for every model/prompt/task combination and measuring its performance.

Activate the environment and run the script:
```bash
source venv/bin/activate
./run_all.sh
```
This will generate all implementations, run the measurement harness for each, and may take several hours to complete. All results are saved to `data/derived/runs.csv`.

### 5) Analyze Results
After the runs are complete, compute the "Green Capacity" (GC) and Percentage Difference (PD) metrics:
```bash
make analyse
```
This creates `data/derived/pd_table.csv` and `data/derived/gc_table.csv`.

You can explore the full analysis in the Jupyter notebook:
```bash
# With the venv activated
jupyter notebook analysis/analysis.ipynb
```

## Repository Map

- `prompts/` — Prompt templates used for code generation.
- `tasks/task_specs/` — Markdown descriptions of the six software tasks.
- `tasks/generated/` — LLM-generated Python modules, organized by task.
- `tasks/reference/` — Human-written reference implementations for comparison.
- `tasks/validators.py` — Correctness checks for each task's output.
- `harness/generate.py` — Script to generate code from a model using a given prompt and task spec.
- `harness/run.py` — Measurement harness that executes a solution and records performance metrics.
- `analysis/compute_gc.py` — Script to calculate Percentage Difference (PD) and Green Capacity (GC) from raw run data.
- `analysis/analysis.ipynb` — Jupyter notebook for statistical analysis and visualization of results.
- `run_all.sh` — Master script to execute the entire experiment from generation to measurement.
- `Makefile` — Convenience targets for running individual parts of the experiment.
